# 完全性 {#completeness}

リプレイの中身は何も捨てられません。変換ツールが読んだものはテーブルとマッチドキュメントに入ります。それ以外のすべての項目は、サイドカー `<match>.messages.parquet` に丸ごと残されます。そして、マッチドキュメントの `selfCheck.completeness` は、項目の種類ごとに、それがどうなったかを数えます。これは、すべての 3DHeat 変換ツールに共通のルールです: [変換ツールはすべてを残す](https://holdi601.github.io/3DHeat/converters.html)。

![合成リプレイの自己チェック: 見られた、読まれた、残された、失われた項目](../assets/img/completeness.svg)

## 数え方 {#the-count}

項目の種類ごとに、`selfCheck.completeness.types` は次を示します:

| 数 | 意味 |
|---|---|
| `seen` | リプレイが持っている数 |
| `decoded` | 丸ごと読まれた数 |
| `partial` | 一部が読まれ、サイドカーに丸ごと残された数 |
| `raw` | サイドカーに丸ごと残されただけで、読まれなかった数 |
| `lost` | 失われた数。常に `0` |

種類はリプレイ自身のものです: `block <n>`（JSON のブロック）、コンテナー自身のバイト、`packet <type>`。エンティティへの呼び出しには `method <entity type>.<number>` と `property <entity type>.<number>`。`selfCheck.entities.roles` は、どのエンティティの型が録画しているプレイヤーのアバターで、どれが艦船かを示します。誰も知らなかった種類は、その数とともに現れます。

## サイドカー {#the-sidecar}

| 列 | 内容 |
|---|---|
| `time` | リプレイの時計。テーブルと同じ |
| `type`、`name` | 項目の種類。変換ツールがそれを何と呼んでいるか、どこで読んでいるか |
| `entity` | それが属する艦船またはアバター。テーブルの `entity` と同じ |
| `decoded` | そこから読まれた内容。JSON 形式 |
| `payload`、`text` | そのバイト、丸ごと。JSON のブロック、丸ごと |
| `entityType`、`packet`、`method` | 番号 |

行は、パケット、メソッド、エンティティ、時刻の順に並びます。どのエンティティがどのプレイヤーかは、マッチドキュメントの `entities` と `players` にあります。

## 読み取った内容と、その確かめ方 {#what-is-read-and-how-it-was-checked}

- **結果** （15.x、`results`）: その戦闘の ID はストリームのものと同じで、そこにあるすべてのプレイヤーはヘッダーの名簿にいます。
- **ID のブロック** （15.x、`blockIds`）: アカウントと戦闘。テキストとして読むので、どの桁も失われません。
- すべての位置の**ピッチとロール**: ロールは旋回の速さと一緒に決まります。艦船は旋回で傾くからです。ピッチはほとんどいつも 0 です。
- **エンティティ** （`entities`）: それぞれがいつクライアントの視界に入り、いつ出たか。艦船は、出てから戻るまでの間、位置を持ちません。
- **ストリームのバージョン** （`streamVersion`）: ヘッダーのものと同じ。

ほかに読まれたすべて（撃沈、ダメージ、体力、砲弾、魚雷、砲弾の終点、チャット、ピクルされた呼び出し、プレイヤーの記録、位置）は `partial` です。テーブルかマッチドキュメントに入り、サイドカーに丸ごと残されます。

**残されたが読まれていないもの**（`raw`）で、最も大きな種類: テーブルにない位置の更新（艦船が沈んだ後、プレイヤーのないエンティティ）、読み手のない頻繁なプロパティとメソッド、エンティティの作成のプロパティ、そして読み手のないそのほかのすべてのパケット。

## 使えないもの {#not-available}

- サーバーが録画したクライアントに送らなかったもの: ほかのプレイヤーの照準、カメラ、入力、発見されていない敵。リプレイは、1 つのクライアントが知らされたことそのものです。
- エンティティの型、メソッド、プロパティ、統計のキーの名前: それらはリプレイではなく、ゲームの定義ファイルにあります。番号は残されます。
- 艦船の番号に対応する艦船の名前（`--ship-names` を使う）、およびゲームのファイルを必要とするそのほかのもの。
- 15.x より前のクライアントの結果: それらのリプレイには入っていません。
