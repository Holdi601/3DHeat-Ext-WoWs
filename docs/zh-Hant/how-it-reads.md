# 讀取回放的方式 {#how-it-reads-a-replay}

回放是由 JSON 區塊組成的標頭，加上遊戲的封包串流（格式說明見 [`heat3d_ext_wows/bigworld.py`](https://github.com/Holdi601/3DHeat-Ext-WoWs/blob/main/heat3d_ext_wows/bigworld.py)）：

- 第一個區塊，未加密：地圖、客戶端版本、錄製玩家與其船，以及名單——每位玩家的名稱、友方或敵方，以及船的編號。較新的客戶端（15.x）還多了兩個區塊：一個空的，以及錄製玩家的帳號與戰鬥 id（以文字表示），讀入 `blockIds`。結算不在 JSON 中；15.x 把它們保存在串流裡。
- 封包串流：以 zlib 壓縮，並以遊戲所附金鑰進行 Blowfish 加密；讀取這些檔案的社群工具已公開此金鑰。解密後，它包含：
  - 客戶端能看到的每艘船的引擎位置更新（自己的隊伍全程都有，敵人則在被偵察到或靠近時才有），船在移動時每秒數次，不移動時較少；
  - 錄製玩家自己的船，放在自己的封包中，約每秒七次；
  - 開頭一次，玩家紀錄以 pickle 保存的 Python 清單。它們說明串流中哪個實體是哪位玩家。它們的鍵是有編號的，而編號會隨更新而改變，因此讀取器是依據其值找到鍵：保存名單名稱的鍵，以及保存有位置更新之實體的鍵；
  - 伺服器告知客戶端某艘船已沉沒的呼叫：受害者、擊殺者、原因。它是依其形狀找到的（十二個位元組；前兩個是船的實體；每個受害者只出現一次），而非依其編號；
  - 每艘船的傷害：每次命中的（攻擊者，傷害）陣列，位於被命中的船上；以及其血量，即稍早設定的一個屬性；
  - 客戶端被告知的每一輪砲擊與魚雷：砲彈類型、射手、該輪攻擊，以及每發砲彈或魚雷的起點與速度；
  - 砲彈的落點：射手、命中類型，以及每發的位置（15.x 的客戶端上還有砲彈擊中處的更多資料，會被略過）；
  - 聊天：發送者、頻道、一行內容；
  - 送給錄製玩家的 pickle 呼叫：其傷害統計、玩家紀錄的更新，以及戰鬥狀態；
  - 在 15.x 的客戶端上，戰鬥結束時的結算：一個自己的封包，是一個含有戰鬥 id 的 JSON 物件，完整讀入對戰文件的 `results`（遊戲自己的清單，未命名：`commonList`、`privateDataList`、每個帳號的 `playersPublicInfo`……）。

不同版本之間不同的封包與方法編號（自己的船的封包為 43 或 44、沉沒呼叫為 76 或 83、砲彈為 101、102、126 或 127）都是依形狀找到的——見 [`heat3d_ext_wows/stream.py`](https://github.com/Holdi601/3DHeat-Ext-WoWs/blob/main/heat3d_ext_wows/stream.py)——因此改編號的更新不會讓表格變空。找到的編號記錄在對戰文件的 `decoded` 中。

**pickle 是不可信的資料。**回放是來自任何地方的檔案，而 pickle 可以指定要執行的程式碼。它是以一個解pickle器載入的，該解析器會把 pickle 所指定的每個類別或函式都換成無害的替身，因此只會建立純粹的資料，不會有其他結果。測試中會餵給它一個會呼叫 `os.system` 的 pickle。

**沉沒**的時間是呼叫發生的精確時刻。其地點是受害者最後被看到的位置，前提是該時間在五秒之內。**戰鬥的開始**是任何船第一次移動的時刻（船在倒數時是靜止的）。

凡不是表格列的內容，都在[對戰文件](match-document.md)中。

**客戶端被告知的內容**，對自己的隊伍是完整的，對敵人則是部分的：他們的射擊、命中與血量，只在範圍內時才會出現。

**未讀取的內容：**

- 航空器及其中隊（攜帶它們的呼叫尚未拆解）、小地圖的視野更新（經過壓縮）、偵察、戰績徽章、火災與淹水作為獨立事件（它們的傷害記在命中中）、消耗品、佔領點與隊伍分數（沒有定義的實體屬性，無法依形狀區分），以及船的其他屬性（瞄準、舵、速度設定……）。
- 玩家紀錄與傷害統計的鍵編號，無法轉為名稱：遊戲以編號命名，且編號會改變；它們以數字保留。
- 砲彈在落點的額外資料（15.x），以及砲彈或魚雷起點與速度之後的位元組。
- 15.x 之前的客戶端的結算：它們的回放中沒有。
- 船的編號對應的船名：名稱在遊戲自己的參數檔案中，而不在回放裡。

## 讀取是如何核對的 {#how-the-reading-was-checked}

讀取已在 0.9 至 15.x 的客戶端公開回放上核對，每個數值都與回放中另一處給出的值比對：

- **位置：**每艘船的實體都與名單中的一個名稱相符；航向與行進方向相差 0.1 弧度以內；沉沒之後，船的移動少於 0.1 單位。靜止的船更新次數較少。
- **血量：**在客戶端視野內沉沒的每艘船，最後血量都是 0。所有命中中約有一半與其前一秒的血量下降相符；其餘的則與修復或其他命中一起下降。
- **與遊戲自己的統計比對：**在最新的客戶端上，錄製玩家讀取到的傷害與統計相差在 0.1% 以內。在較舊的客戶端上，統計較高：客戶端並未收到每一次命中，或統計計入了比命中更多的項目（尚未解決）。
- **砲彈：**一發砲彈從其船最後已知位置附近幾單位處開始（砲塔分布在船身上）；幾乎每發砲彈的落點，在一分鐘內都會跟隨一次客戶端所看到的射擊。

測試會以相同的格式建立回放，因此本儲存庫中沒有保存任何真實回放。

**未核對的：**0.9.6 之前的客戶端、Lesta 客戶端（Mir Korabley）、超過一場的任務與劇本、公會戰與排位戰，以及哪個船的編號對應哪艘船。
