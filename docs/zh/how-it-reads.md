# 工具如何读取录像 {#how-it-reads-a-replay}

录像由一个 JSON 块组成的文件头，加上游戏的数据包流（格式说明见 [`heat3d_ext_wows/bigworld.py`](https://github.com/Holdi601/3DHeat-Ext-WoWs/blob/main/heat3d_ext_wows/bigworld.py)）：

- 第一个块，未加密：地图、客户端版本、录像播放者及其舰船，以及名单——每位玩家的名称、敌我阵营和舰船编号。较新的客户端（15.x）还增加了两个块：一个空块，以及以文本形式读取、记入 `blockIds` 的录像播放者账号和战斗 ID。结果不在 JSON 中；15.x 将它们保存在数据流中。
- 数据包流，经过 zlib 压缩，并使用游戏内置的密钥进行 Blowfish 加密；该密钥已被读取这些文件的社区工具公开。解密之后，它包含：
  - 客户端能看到的每艘舰船的引擎位置更新（全程包括己方队伍，敌方则在被发现或靠近时出现），在移动时每秒多次，静止时则较少；
  - 录像播放者自己的舰船，位于它自己的数据包中，大约每秒七次；
  - 开始时一次性的玩家记录，为一个 pickle 化的 Python 列表。这些记录说明数据流中哪个实体对应哪位玩家。它们的键是有编号的，而编号会随补丁变化，因此读取器通过其值来查找键：保存名单名称的键，以及保存拥有位置更新的实体的键；
  - 服务器告知客户端某艘舰船已沉没的调用：受害者、击杀者、原因。它通过其结构（十二个字节；前两个是舰船实体；每个受害者只出现一次）识别，而不是通过其编号；
  - 每艘舰船的伤害：每次命中在被命中舰船上的（攻击者，伤害）数组；以及其生命值，一个在此之前不久设置的属性；
  - 客户端所被告知的每一次炮弹和鱼雷齐射：炮弹类型、射手、齐射，以及每发炮弹或鱼雷的起点和速度；
  - 炮弹的落点：射手、命中类型，以及每次的位置（在 15.x 客户端上，还有关于炮弹击中处的更多信息，这部分会被跳过）；
  - 聊天：发送者、频道、内容；
  - 发给录像播放者的 pickle 化调用：其伤害统计、玩家记录的更新，以及战斗状态；
  - 在 15.x 客户端上，战斗结束时的结果：它自己的数据包，是一个带有战斗 ID 的 JSON 对象，被完整读取到对局文档的 `results` 中（游戏自身的列表，未命名：`commonList`、`privateDataList`、每个账号的 `playersPublicInfo` 等）。

在所核对的各版本之间不同的数据包和方法编号（己方舰船的数据包为 43 或 44，沉没调用为 76 或 83，炮弹为 101、102、126 或 127）都通过结构识别——见 [`heat3d_ext_wows/stream.py`](https://github.com/Holdi601/3DHeat-Ext-WoWs/blob/main/heat3d_ext_wows/stream.py)——因此补丁重新编号不会使表格变空。找到的编号保存在对局文档的 `decoded` 中。

**pickle 是不可信的数据。** 录像是来自任何地方的文件，而 pickle 可以指定要运行的代码。因此它使用一个反序列化器加载：对 pickle 所指定的每个类或函数，都给出一个无害的替身，因此它只会构建普通数据，而不会执行任何其他操作。有一项测试会向它提供一个调用 `os.system` 的 pickle。

**沉没**记录的是调用的精确时间。其位置取受害者最后一次被看到的地方，前提是该时间距其沉没不超过五秒。**战斗开始**是任何舰船首次开始移动的时刻（倒计时期间舰船静止不动）。

所有不属于表格行的内容都在 [对局文档](match-document.md) 中。

**客户端所被告知的内容**，对于其自身队伍是完整的，对于敌人则是部分的：他们在处于范围内时的射击、命中和生命值都会出现。

**未读取的内容：**

- 飞机及其编队（携带它们的调用尚未被拆解）、小地图的视野更新（已打包）、侦察、战绩条、火灾和进水（它们的伤害记录在命中中，而不作为独立的事件）、消耗品、占领点和队伍得分（没有定义的实体属性，无法仅凭结构区分），以及舰船其余的属性（瞄准、舵、速度设置……）。
- 玩家记录和伤害统计中作为键的数字：游戏为它们编号，且编号会变化；它们保留为数字。
- 炮弹击中处的额外数据（15.x），以及炮弹或鱼雷起点和速度之后的字节。
- 15.x 之前的客户端的结果：它们的录像中不包含结果。
- 作为名称的舰船编号：名称位于游戏自身的参数文件中，而不在录像中。

## 读取的核对方式 {#how-the-reading-was-checked}

读取过程已在 0.9 至 15.x 客户端的公开录像上进行核对，每个数值都与录像中给出的另一次数值进行比较：

- **位置：** 每艘舰船的实体都与名单中的某个名称相对应；航向与行进方向的差距在 0.1 弧度之内；沉没之后，舰船的移动不超过 0.1 个单位。静止的舰船更新频率较低。
- **生命值：** 每艘在客户端视野内沉没的舰船，其生命值最终都为 0。约一半的命中与之前一秒内的生命值下降相对应；其余的则与修理或其他命中同时发生。
- **与游戏自身统计数据的对照：** 在最新的客户端上，录像播放者读取的伤害与统计数据相差在 0.1% 之内。在较旧的客户端上，统计数据更高：客户端并不会收到每一次命中，或者统计数据包含的不止命中（尚未解决）。
- **炮弹：** 炮弹从其舰船最后已知位置附近几个单位处开始（火炮沿舰体分布）；几乎每一发炮弹的落点，在一分钟之内都会对应客户端所见的一次射击。

测试会以相同的布局生成录像，因此本仓库中不保存任何真实录像。

**未核对的内容：** 0.9.6 之前的客户端、Lesta 客户端（Mir Korabley）、超过一个的行动和剧本、军团战和排位战，以及哪个舰船编号对应哪艘舰船。
