# Канвертаванне запісаў {#converting-replays}

## Крок за крокам {#step-by-step}

1. **Уключыце запіс**: `isReplayEnabled` у `preferences.xml` гульні або
   ўласная налада гульні, дзе яна ёсць. З гэтага моманту гульня захоўвае
   кожны бой у папцы `replays` вашай усталёўкі World of Warships, напрыклад
   `C:\Games\World_of_Warships_EU\replays`.
2. **Адкрыйце тэрмінал** у папцы, куды можна класці вынікі
   ([Перад пачаткам](before-you-start.md)).
3. **Запусціце канвертар** на файлах запісаў або на папках, у якіх яны ляжаць:

   ```bash
   heat3d-wows-replay "C:\Games\World_of_Warships_EU\replays" -o out
   heat3d-wows-replay a.wowsreplay b.wowsreplay -o out
   ```

   `out` ствараецца ў папцы, у якой знаходзіцца ваш тэрмінал.
4. **Прачытайце, што ён піша.** Вы павінны ўбачыць па радку на кожны запіс,
   які заканчваецца табліцай, што ён запісаў.
5. **Адкрыйце вынік** у праглядальніку 3DHeat: `out/<map>/<match>.parquet`
   на ўкладцы «Цеплавая карта», `<match>.match.json` на ўкладцы «Матч». Або
   чытайце іх любым чытачом Parquet ці JSON.

![Запуск на сінтэтычным запісе: канвертаванне, паўторны запуск, пашкоджаны файл, пустая папка](../assets/img/convert.svg)

Малюнак паказвае запуск на запісе, які тэсты будуюць у кодзе (ніякага
сапраўднага запісу):

- запіс сканвертаваны: `<file>: <n> positions of <n> ships at <rate> Hz (own <rate> Hz), <n> sunk, <map> (<client version>) -> <table>`;
- пры паўторным запуску ўжо запісаны матч прапускаецца: `<file>: already written, <table>`;
- файл, які не з'яўляецца запісам: `<file>: not converted: <why>` (у вывадзе
  памылак; статус выхаду 1, астатнія запісы ўсё роўна канвертуюцца);
- запіс не знойдзены: `no .wowsreplay files in <folders>` (статус выхаду 2).

## Параметры {#options}

| Параметр | Па змаўчанні | Што робіць |
|---|---|---|
| `replays` (адзін або болей) | - | файлы `.wowsreplay` або папкі, у якіх іх шукаюць (разам з падпапкамі) |
| `-o`, `--out` | абавязковы | папка, куды пісаць: усярэдзіне па папцы на кожную карту |
| `--force` | выкл. | канвертаваць нанава тое, што ўжо запісана |
| `--ship-names JSON` | - | файл JSON `{"<shipId>": "<name>", ...}`: запісы называюць толькі карабель гульца, які вёў запіс, а астатнія - па нумары |
| `--version` | - | вывесці `heat3d-wows-replay <version>` і спыніцца |
| `-h`, `--help` | - | вывесці параметры і спыніцца |

Параметры ў тым выглядзе, як іх друкуе праграма: [Даведнік каманд](../cli-reference.md).

## Што запісваецца {#what-is-written}

Толькі асобныя файлы: гэты канвертар не піша файл `.3dheat` (праглядальнік
можа спакаваць іх у адзін: [One file a match](https://holdi601.github.io/3DHeat/container.html)).
На запіс, у `out/<map>/` (назва карты без `spaces/`):

| Файл | Што |
|---|---|
| `<match>.parquet` | табліца: пазіцыя кожнага карабля ў часе і кожная падзея там, дзе яна адбылася ([Табліца](table.md)) |
| `<match>.match.json` | дакумент матча: карта, версія кліента, гульцы, патапленні, чат і ўсё астатняе ([Дакумент матча](match-document.md)) |
| `<match>.messages.parquet` | дапаможны файл: кожны пункт запісу, якога цалкам не трымаюць два файлы вышэй ([Паўната](completeness.md)) |

`<match>` - гэта ўласны id бою або назва файла, калі запіс спыніўся да
вынікаў.

## Статус выхаду {#exit-status}

`0`, калі кожны запіс сканвертаваны або прапушчаны, `1`, калі хоць адзін не
ўдаўся (астатнія ўсё роўна канвертуюцца), `2`, калі файл запісу не знойдзены.
