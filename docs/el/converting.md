# Μετατροπή replay {#converting-replays}

## Βήμα προς βήμα {#step-by-step}

1. **Ενεργοποιήστε την εγγραφή**: `isReplayEnabled` στο `preferences.xml` του παιχνιδιού, ή η
   δική ρύθμιση του παιχνιδιού όπου έχει μία. Από τότε το παιχνίδι αποθηκεύει κάθε μάχη στον
   φάκελο `replays` της εγκατάστασης του World of Warships, για παράδειγμα
   `C:\Games\World_of_Warships_EU\replays`.
2. **Ανοίξτε ένα τερματικό** σε φάκελο όπου μπορούν να γραφτούν τα αποτελέσματα
   ([Πριν ξεκινήσετε](before-you-start.md)).
3. **Τρέξτε τον μετατροπέα** σε αρχεία replay, ή σε φακέλους που τα περιέχουν:

   ```bash
   heat3d-wows-replay "C:\Games\World_of_Warships_EU\replays" -o out
   heat3d-wows-replay a.wowsreplay b.wowsreplay -o out
   ```

   Το `out` δημιουργείται μέσα στον φάκελο όπου είναι το τερματικό σας.
4. **Διαβάστε τι λέει.** Πρέπει να δείτε μία γραμμή για κάθε replay, που τελειώνει με τον
   πίνακα που έγραψε.
5. **Ανοίξτε το αποτέλεσμα** στον προβολέα 3DHeat: `out/<map>/<match>.parquet` στην καρτέλα
   Χάρτης θερμότητας, `<match>.match.json` στην καρτέλα Αγώνας. Ή διαβάστε τα με
   οποιονδήποτε αναγνώστη Parquet ή JSON.

![Μια εκτέλεση σε ένα συνθετικό replay: μετατροπή, νέα εκτέλεση, ένα χαλασμένο αρχείο, ένας άδειος φάκελος](../assets/img/convert.svg)

Η εικόνα είναι μια εκτέλεση σε ένα replay που φτιάχνουν τα τεστ μέσα στον κώδικα (χωρίς
πραγματικό replay):

- ένα replay μετατράπηκε: `<file>: <n> positions of <n> ships at <rate> Hz (own <rate> Hz), <n> sunk, <map> (<client version>) -> <table>`·
- τρέχει ξανά, ο αγώνας που έχει ήδη γραφτεί παραλείπεται: `<file>: already written, <table>`·
- ένα αρχείο που δεν είναι replay: `<file>: not converted: <why>` (στην έξοδο σφαλμάτων·
  κωδικός εξόδου 1, τα υπόλοιπα replays μετατρέπονται κανονικά)·
- δεν βρέθηκε replay: `no .wowsreplay files in <folders>` (κωδικός εξόδου 2).

## Επιλογές {#options}

| Επιλογή | Προεπιλογή | Τι κάνει |
|---|---|---|
| `replays` (ένα ή περισσότερα) | - | αρχεία `.wowsreplay`, ή φάκελοι όπου αναζητούνται (και οι υποφάκελοι τους) |
| `-o`, `--out` | υποχρεωτικό | ο φάκελος όπου γράφεται: ένας φάκελος ανά χάρτη μέσα του |
| `--force` | ανενεργό | μετατρέψτε ξανά όσα έχουν ήδη γραφτεί |
| `--ship-names JSON` | - | ένα αρχείο JSON `{"<shipId>": "<name>", ...}`: τα replays ονομάζουν μόνο το πλοίο του παίκτη που καταγράφει, τα υπόλοιπα με αριθμό |
| `--version` | - | τυπώστε `heat3d-wows-replay <έκδοση>` και σταμάτα |
| `-h`, `--help` | - | τυπώστε τις επιλογές και σταμάτα |

Οι επιλογές όπως τις τυπώνει το πρόγραμμα: [Αναφορά εντολών](../cli-reference.md).

## Τι γράφεται {#what-is-written}

Μόνο χωριστά αρχεία: ο μετατροπέας αυτός δεν γράφει αρχείο `.3dheat` (ο προβολέας μπορεί
να τα συσκευάσει σε ένα: [Ένα αρχείο ανά αγώνα](https://holdi601.github.io/3DHeat/container.html)).
Για κάθε replay, μέσα στο `out/<map>/` (το όνομα του χάρτη χωρίς το `spaces/`):

| Αρχείο | Τι είναι |
|---|---|
| `<match>.parquet` | ο πίνακας: η θέση κάθε πλοίου με τον χρόνο και κάθε γεγονός όπου έγινε ([Ο πίνακας](table.md)) |
| `<match>.match.json` | το έγγραφο αγώνα: χάρτης, έκδοση πελάτη, παίκτες, βυθίσεις, συνομιλία και όλα τα υπόλοιπα ([Το έγγραφο αγώνα](match-document.md)) |
| `<match>.messages.parquet` | το βοηθητικό αρχείο: κάθε στοιχείο του replay που τα δύο παραπάνω αρχεία δεν κρατούν ολόκληρο ([Πληρότητα](completeness.md)) |

Το `<match>` είναι το δικό του αναγνωριστικό της μάχης, ή το όνομα του αρχείου όταν η
εγγραφή σταμάτησε πριν τα αποτελέσματα.

## Κωδικός εξόδου {#exit-status}

`0` όταν μετατράπηκε ή παραλείφθηκε κάθε replay, `1` όταν απέτυχε κάποιο (τα υπόλοιπα
μετατρέπονται κανονικά), `2` όταν δεν βρέθηκε αρχείο replay.
